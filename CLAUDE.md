# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Uzbek-language Telegram mafia game bot (aiogram 3, SQLAlchemy 2 async). User-facing brand is **Admiral Mafia**; the package (`mafia_zone`) and the original spec still say "Mafia Zone". Game rules come from `Mafia Zone - Game Guide & Technical Specification.pdf`; the design decisions that fill its gaps are in `docs/superpowers/specs/2026-10-06-mafia-zone-design.md`. All user-facing text is Uzbek (Latin); code comments are Uzbek too — keep that.

## Commands

```bash
pip install -r requirements.txt pytest     # deps (no lint/format tooling in the repo)
python -m mafia_zone                       # run the bot (reads .env: BOT_TOKEN, ADMIN_IDS, DATABASE_URL)
python -m pytest -q                        # full suite, ~6 min (10k+ random-game simulations)
python -m pytest -q -k "not simulate"      # fast run, ~2 min
python -m pytest -q tests/test_engine.py::test_voris_transforms   # single test
node --check mafia_zone/panel_static/app.js   # syntax check for the panel frontend (no build step)
```

- Env (`.env` locally, Railway Variables in prod): `BOT_TOKEN`, `ADMIN_IDS` (comma-separated owner ids), `DATABASE_URL`, plus optional `PANEL_URL` (else `https://$RAILWAY_PUBLIC_DOMAIN`, which Railway only injects on the deploy *after* a domain is generated), `PANEL_SECRET` (else derived from `BOT_TOKEN`), `PORT` (default 8080), `NEWS_URL`. `config.EMOJI_PACK` is hardcoded `""` since 2026-11 (no sticker-set replacement of plain emoji; the env var is ignored). Premium emoji the bot sends: the PRO badge and the 30 role portraits — `config.ROLE_EMOJI` (role code → custom_emoji_id, set `admiral_roles_by_AdmiralMafiabot`, loaded by `emoji.load_roles` at startup), so a role's emoji (first token of `Role.name`) becomes its portrait in every text. Mapped by role code, not read from the set: Telegram strips skin tones from set emoji (🤵🏻 Don / 🤵🏼 Mafiya both become 🤵). A new role needs a new picture added to that set and its id in `ROLE_EMOJI` (`test_role_portraits_every_role_its_own` checks every role has one). Don't reuse a role emoji for anything else in texts. Same set, `config.ICON_EMOJI` (plain emoji → id): 💵 💎 🛡 🌿 📄 ⚖️, team headers 🏘 / 🪙 (neutral; not 👤, which the profile uses) / 🤵 (= Don), night 🌙 🌃, day ☀️ 🌄 — keep those emoji to their meaning in texts. 🎭 Maska has no picture yet. `PremiumEmoji` covers messages, edits, GIF/photo/document captions and caption edits; alerts/toasts (`cq.answer`) and invoices can't carry custom emoji (Telegram), and a button shows only its leading emoji as a premium icon, so put the main emoji first in button labels.
- No `DATABASE_URL` (or empty) → local SQLite `mafia.db`. Railway gives `postgresql://…`; `config.py` rewrites it to `postgresql+asyncpg://`.
- Tests never touch `mafia.db`: `tests/conftest.py` points `DATABASE_URL` at a temp file before `mafia_zone.db` is imported.
- Known flake: `tests/test_money.py::test_concurrent_buys_and_new_users` sometimes fails with SQLite "database is locked" under full-suite load; rerun it alone before treating it as a regression.
- Schema: `db.init()` runs `Base.metadata.create_all` (new tables) then `_migrate` (adds columns listed in `db.COLUMNS` to existing tables). No Alembic — add every new column on an existing table to `COLUMNS`. SQLite returns naive datetimes; compare via `db._aware()`.
- Deploy: `Dockerfile` (copies `mafia_zone/` plus `kun.mp4`, `tun.mp4`), Railway + Railway PostgreSQL, exactly **one replica** (game state, rate limiters, one-time login nonces live in process memory). Bot polling and the web panel run in the same process.

## Architecture

**`engine/` is pure Python and knows nothing about Telegram.** `Game` (dataclass, JSON-serializable via `to_dict`/`from_dict`) takes actions and returns lists of `Event(kind, uid, target, data)`. All game rules live in `engine/game.py`; `roles.py` is data only (team, action kinds, description); `setup.py` deals roles by player count (4–60). Randomness is seeded (`Random(f"{seed}:{day}:night")`) so any game is reproducible.

- Phases: `NIGHT → DAY → VOTING → (CONFIRM) → NIGHT …`, `FINISHED`. CONFIRM (👍/👎 before hanging) only when `Game.confirm` is on.
- `resolve_night()` runs the spec's priority order in one function: 1a block (Kezuvchi) → 1b Aferist steal, Qaroqchi rob → 2 heal/guard/disguise → 3 checks/info → 4 attacks (immunities, heal, Voris transform, items) → 5 revenge (Afsungar/Suitsid) → `_after_deaths` (Aka/Uka link by stored `Game.bros` uids, Serjant→Komissar, Mafiya→Don promotion — Aka/Uka never become Don; if only they are left, the mafia plays on with their `pair` attack and there is no Don) → `_check_win`. The mafia kill is stored as an action owned by the Don, so blocking/stealing the Don affects it; if the Don submits `SKIP` nobody is killed.
- Roles can change mid-night (Ovchi penalty → `tinch`, Voris transform), so `resolve_night` snapshots `roles0` at the start and puts `role` / `killer_roles` into `killed` and `witness` events. Texts must read roles from event data, not from the mutated `Player`.
- Winners (`_finish`): only **alive** members of the winning side; roles that win by dying (Suitsid, Tulki, G'azabkor) get `won=True` at death and keep it; an Afsungar whose revenge took an enemy (`avenged`) wins if TOWN wins. Konchi/Sehrgar/Aferist/Qaroqchi win whenever alive at the end. A living Qotil/Vampir/G'azabkor blocks both TOWN and MAFIA wins and wins solo at ≤2 alive (`_check_win` `killers`). `setup.deal` has balance rules (mafia count `max(1, (n + 2) // 4)`, raised from `n // 4` in 2026-10 when town won ~60% in prod; constants at the top: no Afsungar/Suitsid/Podshoh at ≤7 players, killer neutrals from 12, repeatable town roles from 30) — `test_deal` asserts them.
- Hanging (`resolve_vote`): the unique player with the most votes is hanged, even with 1 vote; "Hech kimga" (`None`) votes don't compete; a tie at the top or no votes → `no_hang`. CONFIRM hangs only when 👍 > 👎 (any tie spares, including 0:0 when nobody pressed). Janob counts 2.
- `last_target` (Doktor/Kezuvchi/Qorovul) is set from the actions that actually ran (a blocked or stolen action doesn't count). Doktor may heal anyone on consecutive nights except himself (no self-heal two nights in a row; `self_heal_used` is a legacy field kept for saved games); Kezuvchi and Qorovul can't repeat the same target.
- A player's number is their index in `Game.players` (`Game.num(uid)`, join order) and never changes when others die: alive lists and vote/night buttons must use it, not `enumerate(g.alive())`.
- Checks reveal the exact role (`_appear` returns a role code; disguise/Sotqin/`doc` → `"tinch"`). `doc` is spent only by mafia/neutral players and covers every check on them that night; Suitsid's shield/verbena are not used against a mafia kill, Tulki's `votesave` is never used (they win by dying). Kezuvchi's block also sets `mute_day` (no vote next day); the checked player gets `texts.CHECKED_YOU`.
- A player who left (`kill_player`: `/leave`, left the group) must never be acted on: `resolve_vote` drops votes by/for dead players, `confirm_tally` counts only alive voters, `resolve_confirm` skips a dead candidate, night `acts` and `_mafia_target` drop dead targets (else a leaving Podshoh got "hanged" and gave mafia the win). `test_simulate_leaves_never_hit_left_players` fuzzes this.
- `Player.score` is a hidden contribution score (kills/checks/saves/blocks/votes by team, +1 per day survived, +2 alive at the end, −2 per missed night action). It only orders `texts.game_over`; never show it to users.
- Items live in `Player.items` (copied from enabled inventory at start). Every protection (`shield`/`verbena`/`doc`/`votesave`, all spent through `Game._use`) works at most once per game, and `shield`/`verbena`/`votesave` never work for an Afsungar (`NO_AFSUNGAR`: he takes his killer with him anyway; the item is not spent) however many the player owns: `_use` records it in `Player.used`; the DB is only decremented per use (`item_used` → `db.change_item -1`), so the rest stay for later games. No message about the limit. Diamond items: `mask` (works only when hanged: `_hang` spends it via `_use` and marks `hanged.masked`, then `texts.shown_role` hides the role in that announcement and in /players (`"mask" in Player.used`) until FINISHED; lists/composition never show "Maskali", a night death shows the real role and keeps the mask; never robbable), `votesave` (`_hang` → `vote_saved`), role picks `r_<role>` (`Game.use_role_picks` swaps roles before `use_tickets`; not spent if the role isn't in this game). Prices: `config.SHOP` (dollars, PRO −25%), `config.SHOP_GEMS`, `config.ROLE_PICKS` (diamonds, no discount); `db.buy` picks the currency via `db.gem_price` and turns the item back ON (an OFF item is never copied into a game).
- 💞 Couple game (`/couplegame` lobby, `/couplestart` = `/start` (in a group `/start` starts the lobby now; the old `/begin` still works but is off the menu), `/couplestop` = `/stop` but only for a couple game): only users with a `/couple` partner may join (checked in `cmd_start` join); at start players whose partner didn't join are dropped (`couple_pairs`). `Game.couple_mode`: no sides — killers may target anyone but self/partner, Podshoh/Suitsid/Tulki side wins are off, `_check_win` ends only when the alive players are one couple (`COUPLE`) or nobody (DRAW). `Game.pairs` (uid → partner): `_after_deaths` loops Aka/Uka + `heartbreak` until stable; both-alive winners get x2 (`finish_game(double=...)`); partners chat with a `+` PM prefix. Lobby/join button have hearts (`texts.couple_lobby`).
- A hanged Afsungar sets `Game.bomb`: on the next night only, the dead player gets the `blast` action (`available_actions`; `night_actors()` = alive + bomber is what `all_acted`, the runner's night prompts and `/testgame` bots iterate). At dawn the chosen player dies regardless of protection (`revenge` event, `avenged` if an enemy). The group feed never shows it, so a mask stays secret.
- Ovchi (since 2026-11) has only `check` at night (no shoot, no "becomes Tinch" penalty). If his own check ran (not blocked/stolen) and both are alive at dawn, `Game.hunt` gets `[ovchi, target]`; the runner PMs the revealed role with a "💀 O'ldirish" button (`h:<game>:<day>`, `cb_hunt` → `Runner.on_hunt` → `Game.hunter_kill`). He may kill only during DAY (`start_voting` clears `hunt`); protections don't apply; killing a TOWN player costs a random `HUNT_FINE` (100–200) 💵 that `db.hunt_fine` moves to the victim (none in couple games). Not pressing = mercy. A day kill can end the game; `_step` sees the phase change.
- Sehrgar's `curse` (since 2026-11) never hits its target: in `resolve_night` step 4 every player whose action that night targeted the cursed player (from `visitors`, after block/steal; the Don via the mafia kill, other curses excluded) gets a `curse` attack (heal/shield/immunities apply); the target can still die of other attacks. Nobody came → `result` `curse_empty`.
- Konchi's `dig` (since 2026-11) collapses with `DIG_DEATH` (10%) chance: without an unused `ironshield` (🪖 Temir qalqon, `SHOP_GEMS` 1 💎, once per game via `_use`) he gets no loot and dies after the attacks step (`collapsed` event, "jasadi N-tunneldan topildi", N in 1..`TUNNELS`; an attack the same night wins and shows its own text); with it → `item_used` + `dig_saved` (public) and the normal loot.
- Every night role can submit `SKIP` ("Hech narsa qilmayman"): it counts as acting (not AFK); the group feed gets `texts.skip_feed` (none for the Don — the morning `mafia_idle` covers it).
- Every night actor gets a private outcome: `Event("result", actor, target, {"kind", "ok", "why"})` → `texts.RESULT` / `ATTACK_OK` / `attack_fail(why)` (mafia kill → `mafia_result` to the team; check/interview/dig/rob/steal have their own events). A failed attack carries `why` (`heal`/`shield`/`verbena`/`immune`/`transformed`/`gone`, plus `blocked`/`stolen` for the mafia) rendered via `texts.WHY`; `mafia_result.killed` is true only if the mafia's own kill landed. Immune targets get `IMMUNE_YOU`, the Advokat is told when a disguise fooled a check, Daydi learns of a survived attack (`attacked`), Qorovul of a `guard_saved`.
- Adding a role = entry in `roles.py`, pool membership in `setup.py`, rule branches in `game.py`, texts in `texts.py` (`ACT_FEED`, `ROLE_PROMPT`), plus a scenario test.

**`runner.py` — one `Runner` per group chat** (registries: `RUNNERS[chat_id]`, `PLAYING[uid]`). It owns the lobby, the phase loop (`_step`: intro → set `meta["deadline"]` only after the intro is sent (a full group budget can delay it up to 60 s) → wait until deadline or everyone acted → resolve under `asyncio.Lock` → announce), and persistence: the whole game state is saved as JSON into `games.state` after every action and phase change; `restore()` resumes running games on startup from `meta["deadline"]`.

- All Telegram sends go through `send()/edit()/_call()`: a global ~25 msg/s queue, a per-group sliding window (`GROUP_PER_MIN = 19`), `RetryAfter` handling, long-text splitting at 3800 chars. Live feed lines (night actions, votes) are always sent one per message, never merged: `_step` spawns `_flush_live` in the background (so a full group budget can't stretch the phase), `feed_lock` keeps their order, and the resolution awaits `_flush_live` before announcing, so the morning summary (one message for the night) always comes after the feed. Don't bypass these for group messages.
- Every `Runner()` registers itself in `RUNNERS`; tests that build one must `r.close()`, or the panel's live-games test sees it.
- `_call()` never raises: Forbidden/BadRequest → `None`, network/5xx errors are retried then `None`, so one failed send cannot abort a game (an exception escaping `_loop` aborts the game). Start background coroutines with `runner.spawn()` (keeps a reference), not bare `asyncio.create_task`.
- Lobbies live in memory only; their message ids are mirrored in the `lobbies` table so `restore()` can unpin/delete them and tell the group after a redeploy. `/game` during an open lobby reposts it at the bottom (`repost_lobby`).
- `runner.BackToGroup` (session middleware, registered before `PremiumEmoji`) appends a `texts.BACK_TO_GROUP` URL button to private messages/edits for a user in `PLAYING` (lobby and game), except ones carrying callback (choice) buttons — vote, night action, 👍/👎 prompts get none; the "tanladingiz" edit after a choice does. It links to the bot's last group message (`LAST_MSG`, recorded from group sends) via `t.me/c/<id>/<msg>`, which only works in supergroups (basic groups get no button). Tests with `FakeBot` bypass session middlewares.
- Inline buttons have no `style` (plain): the only colored ones are the profile item ON/OFF toggles (`profile_kb`, green/red). Don't add colors elsewhere; show state with ✅/❌ in the label.
- Ephemeral messages (Bot API 10.2+, group messages only one user sees; `runner.send_eph` / `runner.eph()`; they skip `_group_slot`, `message_id` is 0 and `ephemeral_message_id` identifies them, edit/delete via the `*_ephemeral_message*` methods; delivery is not guaranteed and they may expire, so nothing may depend on them alone): night-action and vote prompts are sent **both** to PM and as an ephemeral copy in the group (`Runner.eph` uid → id); whichever is pressed shows "tanladingiz" (`handlers.cq_edit`), `Runner.drop_prompt` deletes the other copy, and all ephemeral prompts are deleted at phase end. `handlers.alert` shows group-button warnings as an ephemeral reply (falls back to `show_alert`); the role-card button stays a plain alert on purpose. `handlers.answer_me` answers /top /rules /players /next /help only to the caller (these are `is_ephemeral` in the group menu), and every group refusal/"not now" reply (/game while a game runs, /start /extend /stop with nothing open, not admin/starter, /leave when not playing or not Pro, /couple and /uncouple errors, PM-only commands typed in a group → `cmd_pm_only` `texts.PM_ONLY`). /settings is ephemeral to the admin (`SET_EPH` uid → (chat, eid) so `cb_settings` can edit it; anonymous admins get a normal message; ❌ Yopish `s:close` deletes it). /couple and /uncouple work but are not in the group command menu (owner's request). Public on purpose: the /couple request, `couple_broken`, /mycouple's couple, lobby/extend/leave announcements. The new-member welcome photo is ephemeral in the group (PM fallback). The confirm 👍/👎 message stays public.
- Night actions and votes are cast in private chat via inline buttons; callback data embeds `game_id:day` so stale buttons are rejected. Unanswered prompts (`Runner.prompts`, uid → msg_id, in memory) are deleted in the background when the phase ends; a stale button pressed later (e.g. after a restart) answers "Kechikdingiz" and deletes its private message (`handlers._stale`/`_late`).
- Group admins can delete any bot message, and bots get no delete updates. Nothing that decides the game may live only in a group message: 👍/👎 confirm buttons are also sent to every voter's PM (`cb_confirm` resolves the runner via `PLAYING`), and a failed edit means "deleted" → the confirm/lobby message is re-sent (`_edit_confirm`, `_refresh_lobby`). `confirm_shown` skips no-op edits so "not modified" never triggers a re-send.
- `/testgame N` (owner only) adds fake players with uids `>= FAKE_BASE`; they act randomly and are never messaged.

**`texts.py`** turns events into messages: `morning(g, ev)` returns `(public_messages, [(uid, private_text)])`. All HTML must stay within Telegram's subset (`b`, `i`, `s`, `a`, `code`, `tg-emoji`) — tests validate generated messages. Render player names through `mention()`/`pm()` (links + PRO badge) or `dn()`/`nm()` (plain/escaped, PRO nickname applied at render time) — never store the nickname into `Player.name`. Role names (`role()`) and team names in the role card and /rules (`team_label()`) and the name tags `pro.PRO_TAG`/`VIP_TAG`/`CREATOR_TAG` (𝐏𝐫𝐨 𝐕𝐢𝐩 𝐂𝐫𝐞𝐚𝐭𝐨𝐫, in text and button labels) are rendered in math-bold; everything else (composition headers "🤵🏻 Mafiya - 3" and "Jami", profile labels, PRO, leaderboard titles) uses plain Telegram `<b>` — keep that split.

**`handlers.py`** — aiogram router. Handler order matters: the catch-all `@router.message(GROUPS)` (`on_group_message`, enforces who may write during a game: bot owners (`ADMIN_IDS`) always, numbers for everyone, `!`-prefixed for group admins, normal text by day for alive players and for any Pro who is dead or not playing) must stay at the end of the file. A callback outer middleware (`drop_double_taps`) ignores the same `(user, callback data)` within `TAP_GAP` = 1.5 s (no double purchases/PRO/votes); a day vote is final (`Runner.on_vote` rejects a second one) and a repeated identical night choice doesn't re-notify mafia mates. Edited messages are intentionally not checked (number → text edit is a deliberate loophole). A global `@router.errors()` handler swallows exceptions. An outer middleware (`drop_commands`) deletes every `/command` addressed to the bot in groups after handling. Admin checks go through `is_admin(bot, chat, uid, msg)` — pass `msg` so anonymous admins (`sender_chat == chat`) count. Telegram gives every post made as a channel the same fake `from_user` (Channel_Bot), so nobody may write in a group as a channel: `drop_commands` deletes such a message without running any handler and posts `texts.AS_CHANNEL` (at most once per `CHANNEL_WARN_GAP` s per group; anonymous admins and `is_automatic_forward` posts of a linked channel pass), `_user` returns None for any `sender_chat` message, and a reply to a channel post is never a `/couple` or `/send` target.

- Prank lock: a `settings` row `couple_lock` = `{"v": [uid1, uid2]}` (written by hand at the owner's request, both agreed) makes that couple's `/uncouple` answer `texts.COUPLE_LOCKED` (`db.couple_lock`, read on every call); delete the row to lift it. The ids live only in the DB, never in the repo (it is public). Same idea, `settings` row `name_lock` = `{"v": {"<uid>": "Creator's"}}` (loaded by `db._apply` into `pro.FORCED` at startup, so a change needs a restart): that user's name is shown as the given text everywhere (over nickname and real name, still fancy if Pro) and `/nickname` answers `texts.NICK_LOCKED`.
- New group members (`on_join`, `F.new_chat_members`) get `mafia_zone/welcome.jpg` + `texts.join_greet` as an ephemeral message in the group (only they see it, even if they never opened the bot), falling back to PM; the "joined" service message is deleted from the group. The "pinned a message" service message is deleted when the bot itself pinned (`on_pinned`); people's pins stay.
- Group timers (`/settings`): ➖/➕ per timer within `config.TIMER_RANGES` (min, max, step; lobby up to 24 h, day 3 h, night/vote 1 h; the step grows to 1 min from 5 min and 10 min from 1 h; the panel uses the same ranges, `GSET` in app.js mirrors them). Times render via `texts.dur`; the lobby countdown via `texts.left_str` (whole minutes rounded up, seconds in the last minute, refreshed every 10 s then).
- `/kick` (reply or `/kick <number>`) is for bot owners (`ADMIN_IDS`) only — group admins are silently ignored. It removes a player with no fine: from the lobby, or in a game via `Runner.leave(uid, kicked=True)`, where the `left` event renders "o'yindan chiqarildi". It is deliberately not in the public command menu.
- Anti-farming rules (values in `config.py`, used by handlers): `/leave` is Pro-only (any tier), in the lobby too (`texts.leave_only_pro` for others), and for Pro it is free, unlimited and not counted (the old 5/day + confirm + fine flow was removed in 2026-11); a non-Pro who leaves the group mid-game is fined `LEAVE_FINE` at once (`on_left`, `LEAVE_FREE = 0`; balance may go negative); balance `<= DEBT_LIMIT` cannot join; the referral bonus is paid at once when the invitee first opens the bot via the ref link (`db.pay_referrals` in `cmd_start`, once per invitee; the call in `Runner._finish` only pays old pending ones); sending money/diamonds and claiming giveaways have no games requirement (the `SEND_GAMES`/`CLAIM_GAMES`/`REF_GAMES` rules were removed at the owner's request in 2026-11); a repeated claim answers `GIVEAWAY_TAKEN` (or `GIVEAWAY_NO` when finished) as an alert; a claim within `CLAIM_DELAY` s of the giveaway message (auto-clicker bots) locks that user out of it (`handlers._shown`/`_early`, in memory, cleared in `expire_giveaway`); only current group members can claim (`get_chat_member`, fails closed). AFK kicks count only missed night actions of roles that have one (votes never count). There is no daily bonus.
- `config.DIAMONDS_OFF` (False since 2026-10-09; True closes) every diamond purchase — PRO for diamonds, Xarid, gem shop items/role picks, Stars→diamonds (`pre_checkout` rejects `dm:` too) — with `texts.DIAMONDS_OFF` ("hali ishlamayapti"); buttons stay. `tests/conftest.py` turns it off for the suite; `tests/test_diamonds_off.py` checks it on.
- PRO's Stars screen (`pro_kb`) also shows `texts.card_note()` + `handlers.card_btn()` → card payment via `t.me/<config.CARD_ADMIN>`.
- Diamonds by card (`cb_card`): 💎 Olmos → o'zim/birov → `gem_shop_kb` (packs `config.DIAMOND_SUM` in so'm, same packs as `DIAMOND_STARS`, plus "Stars orqali to'lash") → `db.create_card_order` (`card_orders`, shown as `TOP-<id>`) → payment screen with the cards (`config.cards()`: `"uz"` and `"xorij"` = abroad, e.g. Uzum Bank Visa for Russia, each {n number, o holder, t bank-linked phone, b bank, k type}; entered in the panel (Iqtisod → To'lov kartalari, owner only, `/api/cards`, `panel.clean_card` validates, audit shows only the last 4 digits) and stored in the `settings` row `cards`, never in git; an empty `"uz"` falls back to the `CARD_NUMBER` env var; none = card closed), copy button per card, cancel. The screen is a **widget** (`mafia_zone/vidjet.py`, Bot API 10.4 `sendWidget` via its own `TelegramMethod`, aiogram 3.31 lacks it): a new message (the menu message is deleted, `card_orders.msg_id` keeps it), tabs «O'zbekistondan / Chet eldan» when both cards exist, copy buttons, timer, steps; no logo, only «ADMIRAL MAFIA» (owner's request). Its state is pushed by the bot (`handlers._card_state` → `editMessageWidgetData`: paid → t, approved → a, rejected → r with the reason, cancelled → b); expiry is computed in the card. The buttons stay under the message (no `widget_query` handling). A rejected widget falls back to the old text screen with both cards. `show()` deletes a widget when it has to send the next menu as a new message ("Orqaga"). Limits (checked in `tests/test_card_widget.py`): HTML ≤ 3900 bytes zlib, `chat_data` ≤ 1 KB, no `opacity`/`filter`, text only via `textContent` (holder/bank come from the panel); it sets `ASK[uid] = "chek:<id>"` (only for nagging on text). A receipt photo/document (`on_check`) is matched to the payer's newest `new` order from the DB (`db.open_card_order`, so it survives a redeploy), must arrive within `CARD_ORDER_MIN`, and moves new→paid (`check_file`, `check_uid` = file_unique_id; a receipt already used on another order adds a ⚠️ line for the admin; if no admin could be reached the user is told to write `CARD_ADMIN`) and is forwarded to every `ADMIN_IDS` owner with the order caption and buttons approve / 3 reject reasons (`texts.REJECT_WHY`, `cb_order_admin`, `oa:<id>:<1|n|s|c>`); `db.approve_card_order` moves paid→approved and credits the target in one transaction (plus a `payments` row `card:<id>`), so a second press does nothing. No automatic bank detection. `send_photo` bypasses `PremiumEmoji`, so the caption strips `USER_MARK` itself.

## Working notes

- When patching files from the shell, write the Python patch script with the Write tool (scratchpad) and run it; `\\n` inside Bash heredocs has repeatedly turned into real newlines and broken string literals, and Edit is safest for single replacements.
- Write plain Unicode emoji in texts. `emoji.py` (session middleware) can swap emoji from an `EMOJI_PACK` sticker set for animated custom emoji, but the pack is off (`config.EMOJI_PACK = ""`), so it now only strips `USER` marks and falls back to plain if a relayed custom emoji is rejected. Each role's emoji (first token of `Role.name`) must be unique.
- Text a player typed and the bot relays (last words, ghost/mafia chat, Donishmand, `+` partner PM) must go through `texts.said(text, msg.entities)`: it keeps their premium (`custom_emoji`) emoji, drops other formatting, escapes HTML, and wraps it in `USER_MARK` (U+2063) so `emoji.premiumize` leaves their plain emoji alone; the middleware strips the marks before sending.
